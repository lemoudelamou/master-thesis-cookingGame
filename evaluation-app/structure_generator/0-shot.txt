YOUR TASK
Given a recipe, generate TWO JSON files:
- File 1: process.json (Game Mechanics)
- File 2: taskTexts.json (Localization – German)

Let's think step by step

================================================================================
REFERENCE: DATA STRUCTURES
================================================================================

Use the following two JSON Schemas as the output.

1) PROCESS_JSON_SCHEMA
- Root object
- Required: tasks, transitions
- No additional properties at root

tasks:
- array of objects
- required fields: name, info, description, openIcon
- no additional properties
- supported optional fields:
  activeIcon, doneIcon, cursorBitmap, cursorHotspot, CursorHotspot, hoverBitmap,
  canHaveAlternativeDonePosition, customPositionOffsetMouse, customExtentOffsetMouse,
  openPosition, donePosition, activePosition,
  openSound, doneSound, activeSound,
  activeTime, activeToDone, userMoveActiveToDonePosition, unopenedToOpen,
  openPreview, speech, feedback
- openPosition/donePosition/activePosition enum:
  stoveLeftTop, stoveLeftBottom, stoveRightTop, stoveRightBottom,
  countertopLeftTop, countertopLeftBottom, countertopRightTop, countertopRightBottom,
  oven, cuttingboard
- binary flags are strings matching ^[01]$
- numeric values are stored as strings matching ^[0-9]+$

transitions:
- array of objects
- required fields: name, parent, child
- no additional properties
- optional fields:
  tool, sound, automatic, mandatory, lob,
  minigameAction, minigameMaxTime, minigamePosition, minigameMaxScore,
  additiveOpenIcon
- binary flags are strings matching ^[01]$
- numeric values are stored as strings matching ^[0-9]+$

2) TASKS_TEXT_JSON_SCHEMA
- Root object
- Required: titles, descriptions, informations, feedbacks, additionals
- No additional properties at root

titles: Short names/labels for each task, referenced by description keys 
- array of { key, value }
- key pattern: ^desc_[0-9]+[a-zA-Z]*$

descriptions: Detailed instructions for each task, referenced by info keys
- array of { key, value }
- key pattern: ^info_[0-9]+[a-zA-Z]*$

informations: Positive reinforcement messages shown when completing significant steps,
referenced by feedback keys
- array of { key, value }
- key pattern: ^info_[0-9]+[a-zA-Z]*$

feedbacks: References to ingredients
- array of { key, value }
- key pattern: ^feed_[0-9]+[a-zA-Z]*$

additionals: Display tips.
- array of { key, value }
- any string key allowed

Return valid JSON only.

PHASE 2: GENERATE JSON FILES

STEP 2A: Generate process.json
- Follow the exact structure described in the PROCESS STRUCTURE reference above
- Include only the fields that are relevant for each task/transition (omit fields that have no applicable value)
- Justify every included field in your analysis (Phase 1) before writing it here
- All values must be in German
- Use camelCase for value names

STEP 2B: Generate taskTexts.json
- Follow the exact structure described in the TASKTEXTS STRUCTURE reference above
- Use sequential zero-padded numbering for all keys (info_00, info_01, desc_00, desc_01, feed_00, ...)
- Write all content in clear, imperative German
- Titles (desc_XX): short and noun-based (e.g. "Tomaten waschen")
- Descriptions (info_XX): action-oriented full sentences (e.g. "Wasche die Tomaten unter fließendem Wasser ab.")
- Feedbacks (feed_XX): positive and encouraging (e.g. "Super! Die Soße ist fertig.")
